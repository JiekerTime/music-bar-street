后端设计入口

一期用一个模块化 Spring Boot 服务，PostgreSQL 保存业务数据，Redis 存会话、验证码和缓存，图片与视频接阿里云 OSS、VOD。PG 和 Redis 先同机部署，按实际需要再拆。

这次把设计分成几份，方便对应实现和检查：

  • 系统设计：模块、调用关系和编码约定。
  • 数据设计：表、关系、唯一约束、档期与事务。
  • 状态与权限：参与方、运营、状态转换和异常。
  • 接口约定：输入、结果、幂等、分页和错误。
  • 媒体与消息：上传、播放、审核、回调和基础聊天。
  • 会员与费用：购买入口、权益、估算和实际收款。
  • 部署与交付：同机部署、看板、备份与开发顺序。

设计图目录 放业务流程、系统架构、数据关系、状态、时序、媒体、部署与页面结构；图的源文件也一起提供。

原则还是：提供扩展性，避免过度设计，严格保证编码风格。先交付一次能跑通的演出合作，直播、打赏、钱包和微服务拆分往后放。

当前只有设计文档、原型和设计图，没有业务后端实现。
