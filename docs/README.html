设计文档

这套设计围绕一场演出合作展开。先看业务，再看系统与数据，最后看接口和怎样交付。图和文字说的是同一套规则，业务后端还没有实现。

资料 解决什么问题
商业思路 双方为什么用，会员和服务费准备怎么试
产品流程 入驻、需求、邀约、谈条件、订单和完成
系统设计 模块怎么分，为什么一期用一个服务
数据设计 对象关系、表、约束和关键事务
状态与权限 谁能做什么，哪些状态能变，异常怎样留记录
接口约定 请求、结果、分页、幂等和错误码
媒体与消息 OSS 图片、VOD 视频和基础聊天怎样接
会员与费用 会员权益、购买入口、服务费统计和收款的区别
部署与交付 PG、Redis 同机部署，看板、备份、开发顺序与验收
页面职责 各页面负责什么，哪些属于一期
低保真原型 一期页面结构、操作与异常状态
怎么试点 用实际合作验证哪些问题

打开设计图目录 可以看业务流程、系统架构、数据关系、状态、确认时序、媒体、部署和页面结构。每张图都有 SVG 和 Mermaid 源文件，修改设计时请一起更新。

公开原型使用重新绘制的灰色线框图，描述需求投递和主动邀约两条路。现有 UI 仅保存在本地。

还需要业务方决定

商家会员的价格和额度、服务费向谁收和何时收、取消费用、争议处理时限，以及手机号登录的服务商都没定。当前设计给这些事留了位置，实际收费或处理争议前要把规则补上。
